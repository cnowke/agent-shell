* Findings and design decisions

Streaming Codex terminal deltas caused repeated copies and re-rendering of
the growing output. The fix retains reversed lists of original chunks,
inserts the first chunk immediately, and batches later literal appends using
the existing stream-render timer. Complete output is assembled for final
rendering and transcripts when a command completes or is interrupted.

- The generic render queue also accumulates chunks without copying its whole
  pending body on every append. It preserves nil-versus-empty semantics and
  text properties.
- Existing =:render-body= handling selects literal insertion. An earlier
  design with eight extra queue parameters was removed.
- Codex metadata remains in =agent-shell-openai.el=. Core rendering and
  finalization helpers live in =agent-shell-tool-output.el=.
- The preview branch adds a limit of 32,768 /characters/ to live terminal
  output. Full final output and transcripts are preserved. There is no new
  =defcustom=; the cap is separate from the batching fix.

Review caught a history-restore bug: =first-last= replay can omit a tool's
later completion or replacement snapshot. Finalization now uses the chunks
retained by the preview actually rendered. A provider cache can already
contain later updates from omitted turns, so it cannot determine the visible
prefix. Completed cache entries are released correctly.

Regression coverage includes omitted completions and replacement snapshots,
metadata-only restore, background continuation, request success/cancellation/
error callbacks, actual cleanup, interleaved tools, chunk boundaries, timers,
folds, and transcript preservation.

* Performance evidence and its limits

Matched synthetic source workload: seven buffers, 512 KiB of output per
buffer, 16 KiB flush intervals, and 120 previous labeled turns per buffer.

| Version                  | Streaming seconds |
|--------------------------+-------------------|
| Tested upstream 4280a74  |            33.251 |
| Batching ff7ea3f         |             4.144 |
| Preview d547e78          |             4.013 |

A 14 MiB single-buffer burst took 0.321 seconds streaming plus 0.323 seconds
completion on batching; preview took 0.276 plus 0.321 seconds. Both saved
14,680,157 transcript characters. The capped live buffer contained 32,877
characters including surrounding UI.

These are synthetic results. A short live observation had too little traffic
to establish an overall CPU reduction. Earlier profiling found substantial
chat-label refresh cost, consistent with [[https://github.com/xenodium/agent-shell/issues/943][upstream issue #943]]. That is a
separate bottleneck. Recheck upstream issue and PR status before relying on
their current state; no chat-label refresh fix was implemented here.
